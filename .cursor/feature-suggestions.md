# Abworkbench 功能建议清单

> 面向当前产品形态：Electron 桌面工作台（仪表盘 / TaskFlow / 番茄 / 习惯 / 笔记 / 天气 / 启动器 / Mini / 摸鱼阅读 / 快速捕获）。  
> 时间约定：**一律按北京时间（Asia/Shanghai）** 计算「今日 / 到期 / 切日」，不依赖「系统本地时区是否碰巧是东八区」的说法。  
> 优先级：P0 补齐已有半成品 · P1 高杠杆体验 · P2 差异化能力 · P3 探索项。

---

## 时间约定（先定死）

| 建议 | 说明 |
|------|------|
| 全局 `Asia/Shanghai` | `todayStr` / 提醒 `dueAt` / 统计切日统一走北京日历日，避免系统时区被改成 UTC 时错乱 |
| 展示层 | UI 文案写「北京时间」或默认不提时区；导出报表文件名用北京日 |
| 不要再强调「东八区误差修复」 | 对本项目用户心智：只要保证北京时间正确即可 |

---

## P0 — 补齐已有半成品（投入小、收益确定）

### 1. 提醒中心（独立管理面）
**现状**：创建有入口，列表散落在仪表盘卡片 / Mini / Header，无统一管理，`repeat` 字段存了但不滚动。

**建议功能**：
- 侧边栏或设置旁的「提醒」页：列表 / 筛选（逾期、今日、即将、已完成）
- 编辑标题、到期时间、重复（每日 / 每周 / 每月 / 工作日）、关联项目
- 完成时：`once` → done；有 repeat → 自动滚到下一期并保持未完成
- 批量：延后 30 分 / 1 小时 / 到明天 9:00（北京时间）
- 从命令面板 / 启动器「提醒」直达本页

### 2. 统计页对齐 TaskFlow
**现状**：仪表盘已映射 TaskFlow；`StatsPage` 仍可能读 legacy `todos`，任务维度易为 0。

**建议**：统计页任务数据源与仪表盘同一套映射；优先分布支持 `urgent`；导出周报任务数与仪表盘一致。

### 3. 生产力趋势真实数据
**状态**：已落地（`offlineAdapter.productivityTrends` → `buildProductivityTrends`；支持天数；空态「暂无数据」）。

### 4. 番茄三套计时器统一
**状态**：已落地（`activePomodoro` sessionStorage + claim/pause/resume；主 / TaskFlow / Focus 互斥；Header/Mini 同步暂停继续）。

**原建议（已实现）**：
- 单一「活跃番茄」状态（sessionStorage）
- 任一处开始时，其它入口暂停并显示「进行中 / 已接管」
- Header / Mini 倒计时与暂停继续写入共享状态
- 完整「跳转到所有者」仍可增强，但不阻塞互斥

### 5. 命令面板动作名实相符
- `start-pomodoro`：进入番茄页并尝试开始（或聚焦运行中计时器）
- 宏「周报 / 今日复盘」：生成后自动打开笔记或预览面板，而不仅是写文件

## P1 — 高杠杆体验（强烈建议排期）

### 6. 今日作战板（Daily Brief）
早间一屏：
- 今日到期 / 逾期任务 Top N
- 到期提醒
- 未完成习惯
- 番茄目标进度
- 一键：「开始第一个任务的 Focus」「打开快速捕获」「延后全部非紧急」

晚间复盘宏可跳转到同一面板的「复盘模式」（已完成清单 + 写 3 行笔记模板）。

### 7. 时间块日历（TaskFlow 强化）
- 日/周视图拖拽排程（estimatedMinutes → 块长度）
- 未排期任务池侧栏，拖入某小时
- 与番茄：「下一块开始时自动开番茄」
- 冲突检测（重叠块提示）

### 8. 跨模块双向链接
- 任务 ↔ 笔记：任务详情「关联笔记」；笔记 front-matter / 底部链接回任务
- 任务 ↔ 习惯：习惯打卡可记「关联任务耗时」
- 提醒 ↔ 任务：提醒「转为任务」或「打开关联任务」
- 全局搜索已有雏形，补「在结果中显示模块徽章 + 最近打开」

### 9. 快速捕获升级为「全能 Inbox」
- 模式：任务 / 笔记 / 提醒 / 支出 / 健康（支出与健康现多为笔记模板，可升为结构化本地集合）
- 剪贴板预填；截图附件（已有 captureScreen 可接到笔记）
- 自然语言：「明天下午 3 点 提醒 交材料 每周」→ 正确北京时间 dueAt + weekly
- 捕获历史（最近 20 条，可撤销）

### 10. Mini 窗 2.0
- 当前番茄倒计时 + 一键暂停
- 今日 Top 3 任务完成按钮（已有任务列表可强化）
- 透明度 / 置顶 / 鼠标穿透可选（与摸鱼阅读能力复用）
- 位置记忆；双击托盘打开 Mini 而非主窗（可设置）

### 11. 启动器能力扩展
- 剪贴板历史（最近 N 条文本，点击粘贴或建任务）
- 计算器 / 翻译已有，补「汇率 / 单位换算」轻量意图
- 书签 / 常用文件夹固定区（已有 recent apps，可加「工作目录」）
- 对选中文件：用默认程序打开 / 在资源管理器显示 / 加入索引项目

### 12. 备份与同步（仍可本地优先）
- 定时自动备份（每日北京时间 21:00）到用户选定目录
- 备份 diff 预览（任务数、笔记数变化）
- 可选：WebDAV / 坚果云 / 本地网盘子文件夹同步（不必上云账号体系）

### 13. 通知中心（可操作）
- Header 下拉不只是摘要：每条可「完成 / 延后 / 打开」
- 免打扰时段（如 23:00–8:00 北京时间只攒着不弹系统通知）
- 按类型开关：任务 / 提醒 / 习惯 / 番茄

## P2 — 差异化（贴合 Abworkbench 气质）

### 14. 摸鱼阅读 2.0
- 书架：进度条、最近阅读、标签（工作摸鱼 / 小说）
- 生词本 / 划线列表 → 一键生成笔记
- Boss Key 一键切到「假装工作」伪装页（已有伪装相关 IPC 可做深）
- 阅读目标：每日 N 章 / N 分钟，计入仪表盘「今日成长」而非仅番茄

### 15. 工作模式（Workspace Modes）深化
**状态**：Deep Work 已落地（免打扰 + 跳转番茄并开始 + 锁摸鱼阅读）；Focus 仍隐藏天气/笔记。Review 模式（复盘模板）未做。

### 16. 能量 / 优先级自动排程
TaskFlow 已有 `energyLevel`：
- 「根据当前时段推荐任务」（上午高能量、午后低能量）
- 一键生成今日排序（紧急 × 能量 × 预估时长）

### 17. 项目仪表盘
按 category/project：
- 完成率、逾期、最近活动、关联笔记数
- 项目巡检宏落地为该页的「健康分」

### 18. 模板库
- 任务模板（周报、发版检查清单、面试准备）
- 笔记模板（会议纪要、复盘、读书笔记）
- 提醒模板（吃药、站立、提交日报）
- 从命令面板「模板：」前缀选用

### 19. 习惯 2.0
- 频率：每日 / 工作日 / 自定义周几（若尚不完整）
- 习惯栈：完成后建议下一个
- 与番茄：完成 N 个番茄自动勾选「深度工作」习惯
- 月历热力与断签补打卡（需确认策略，避免作弊感）

### 20. 桌面小组件 / 第二屏
- 只读「今日三件事」小窗
- 或 Windows 侧边栏式窄条（任务 + 番茄）

## P3 — 探索项（有价值但别抢主线）

### 21. 外部日历双向
只读 Google / Outlook / 系统日历 ICS 导入；或导出 TaskFlow 为 ICS（导出能力部分已有，可做订阅文件自动更新）。

### 22. 轻量 AI 助理（可选、可关）
- 把杂乱 Inbox 文本拆成任务列表
- 根据今日未完成生成「晚上怎么收工」建议
- 本地优先：可先做「规则引擎 + 模板」，模型接入作为高级选项

### 23. 多配置 / 多人物
「工作」与「生活」两套任务库切换（或标签强隔离），备份互不影响。

### 24. 团队向（谨慎）
本产品偏个人桌面；若要做，仅「只读共享周报 Markdown」即可，不要上完整多人协同。

### 25. 插件化启动器
意图脚本（用户 JS/JSON）：输入匹配 → 打开 URL / 跑命令。维护成本高，建议等核心稳定后再做。

## 按用户旅程的打包建议（方便排期）

### 包 A「提醒闭环」（约 1–2 天）
提醒中心 + repeat 滚动 + Header 可操作 + 延后预设（北京时间）。

### 包 B「数字可信」（约 1–2 天）
StatsPage 对齐 TaskFlow + 真实趋势 + 北京时间切日写死 Asia/Shanghai。

### 包 C「专注一体」（约 2–3 天）
**状态**：已落地（番茄互斥 + Deep Work 自动免打扰/番茄/锁摸鱼）。

### 包 D「今日流」（约 2–3 天）
Daily Brief + 捕获 Inbox 升级 + 晚间复盘落笔记。

### 包 E「排程」（约 3–5 天）
**状态**：时间块拖拽排程已落地；能量排序 / 项目仪表盘仍待做。

---

## 不建议优先做的事

- 完整账号云同步 / 多端实时协作（偏离当前本地桌面定位）
- 重做 UI 视觉大改版（现有玻璃拟态体系宜渐进）
- 应用内插件市场（启动器已明确偏集成而非市场）
- 把支出/健康做成重型财务/医疗系统（保持轻量结构化记录即可）
