# 项目工作台（局域网协作）设计

**Goal:** 用轻量「项目工作台」替换默认任务流体验：按项目隔离内容；个人本机管理；局域网「一人开房」后出现「所有人」公开池与负责人策展的「主线」；砍掉旧 taskflow 的臃肿默认面。

## 决策摘要

| 项 | 选择 |
|----|------|
| 简化力度 | 内核重做（非渐进隐藏） |
| 痛点范围 | 入口 + 字段 + 代码一并收敛 |
| 架构 | 主机权威 + 本地个人（方案 1） |
| 局域网 | 一人开房，他人 IP/短码加入；主机在则共享可用 |
| 项目 | 独立内容容器；每项目各自「个人 / 所有人 / 主线」 |
| 主线 | 策展板：仅负责人从个人/池拖入；代表团队真正在做的事 |
| 离线 | 仅个人 + 本机主线；无「所有人」；自己可把自己的任务拉进本机主线 |
| 任务模型 | 轻量核心字段；三态状态；可选 dueDate |
| 旧 taskflow | 导入为项目个人任务；默认可保留「经典」入口，不双写 |
| 同步冲突 | 主机后写覆盖；v1 不做 CRDT |

## §1 空间与权限

### 项目（Project）

新建项目 = 独立内容容器。打开项目后只看到该项目下的任务，不跨项目串数据。

### 项目内三层空间

| 空间 | 谁看得见 | 谁能写 | 存哪 |
|------|----------|--------|------|
| **个人** (`personal`) | 仅自己 | 自己 | 本机 |
| **所有人** (`pool`) | 已加入该主机房间的人 | 任何人可「提交」；带作者标识 | 主机 |
| **主线** (`mainline`) | 项目成员（连上时）；离线时仅本机主线 | **负责人**可从个人/池拖入；离线时自己可把个人任务拖入本机主线 | 连上→主机；离线→本机 |

### 连接规则

- 未连局域网：只显示 **个人 + 本机主线**；不出现「所有人」。
- 一人「开房间」→ 其他人加入 → 出现「所有人」，团队主线以主机为准。
- 主机下线：共享池/团队主线不可用或只读；个人与本机操作不受影响。

### 本机主线 vs 团队主线（切换规则）

- **首次开房（主机）：** 若该项目尚无团队主线，用主机当前「本机主线」快照作为团队主线初始状态。
- **加入者连上：** 主线 UI 显示主机权威版本；本机主线仍保留在本地，但不与团队主线自动双向合并。
- **断线后：** UI 切回本机主线；断线期间对本机主线的改动只留在本机。
- **重新连上：** 再次以主机团队主线为准。若本机主线在断线期间有新增 promote，v1 **不自动合并**到团队主线；提供「把本机主线未同步项提交到池 / 请负责人拉取」的显式操作（避免静默覆盖或静默合并造成丢失感）。
- **非主机用户：** 从未开房时，本机主线仅服务个人策展；连上后工作区主线以团队为准。

### 主线语义

拖入主线 =「立项 / 团队真正在做」，不是简单复制糊墙。池条目保留作者；进主线后仍显示来源人（`authorId` / 来源引用）。

### 负责人

按项目配置（可多人）。只有负责人能把池任务或他人提交拖进**团队主线**。普通人：管个人、提交到「所有人」。

## §2 轻量任务模型与数据流

### 核心 Task（v1 默认字段）

| 字段 | 说明 |
|------|------|
| `id` | 稳定 ID |
| `projectId` | 所属项目 |
| `space` | `personal` \| `pool` \| `mainline` |
| `title` | 标题 |
| `status` | `todo` \| `doing` \| `done`（三态，无 review） |
| `dueDate?` | 可选截止日期 |
| `description?` | 可选短描述（详情抽屉，非必填） |
| `assigneeId?` | 主线可指派；个人默认自己 |
| `authorId` | 创建/提交者（池内标识「谁的」） |
| `sourceTaskId?` | 从个人/池拖入主线时的来源引用 |
| `order` | 排序 |
| `updatedAt` | 同步用 |

**不进默认模型（v1）：** 工时、依赖、循环、精力、活动日志、四象限、子任务数组、笔记数组、标签体系等。需要时再挂扩展，第一版不进 UI。

### 身份（局域网）

本机 `displayName` + 本地 `userId`（开房/加入时在主机注册）。卡片显示作者名，不依赖云账号。

### 关键动作

1. **个人 → 所有人**：`submitToPool`（须已连接）— 推到主机，保留 `authorId`。
2. **个人/池 → 主线**：`promoteToMainline` — 负责人（或离线时自己对自己的个人任务）执行；写 `sourceTaskId`。
3. **主线内**：改状态、排序、指派（主机权威）。
4. **开房/加入**：主机广播项目列表 + 该项目 pool/mainline 快照；之后增量事件。

### 存储

- **本机：** 项目元数据 + 个人任务 + 离线主线副本 + 本地用户档案。
- **主机：** 项目成员/负责人 + pool + 团队主线（权威）。

## §3 页面结构与开房交互

### 信息架构

替换现有任务流**默认**入口：

1. **项目列表** — 新建/打开；连接状态；是否负责人。
2. **项目工作台** — 单一主界面三段（非 5 视图切换）：
   - **个人** — 快速添加 + 列表；完成；提交到所有人；拖入主线（规则见上）。
   - **所有人** — 仅连网显示；作者名；负责人可拖入主线。
   - **主线** — `todo / doing / done` 看板；拖拽改状态与排序。

**不进新壳默认 UI：** 四象限、日历、统计面板、主题定制、每日回顾、周报、Celebration、旧 Header 工具丛。

### 顶栏

当前项目名、连接状态（未连接 / 已开房 / 已加入）、开房或加入、成员/负责人设置（主机侧）。

### 开房 / 加入

- **开房：** 本机起局域网服务，展示 IP + 短码（可选二维码）；开房者为主机；可设可选房间口令（默认空）。
- **加入：** 输入 IP/短码（+ 口令若有）→ 显示名 → 项目列表 → 进入项目。
- **断开：** 回到「仅个人 + 本机主线」；自动隐藏「所有人」。

### 拖拽与权限体感

- 个人 → 所有人：提交（连网）。
- 个人/所有人 → 主线：仅负责人；离线时个人 → 本机主线不限。
- 非负责人拖主线：拒绝并明确提示。

### 编辑

行内改标题/状态为主；详情抽屉最多：描述、dueDate、指派。不用巨型 TaskModal。

## §4 同步边界、错误与旧数据

### 权威与冲突

- **个人：** 本机权威，不与他人合并。
- **所有人 / 团队主线：** 主机权威；客户端发事件 → 主机校验权限 → 广播。
- 同时编辑同一主线任务：后写覆盖 + toast「已按主机版本更新」。v1 不做 OT/CRDT。

### 断线

- 心跳丢失 →「未连接」；隐藏「所有人」；主线回本机副本，并提示团队主线需重连。
- 失败的 `submitToPool` 留在个人并标记待重试；重连后可一键重试。

### 权限失败

非负责人 promote、未知成员写操作：主机拒绝，客户端明确错误，不静默吞掉。

### 安全（v1）

- 短码进房 + 显示名；可选房间口令。
- 仅绑定局域网，不假设公网暴露。
- 不做端到端加密、云账号。

### 旧 taskflow 迁移

- 「导入到项目 · 个人」：映射 `title`、`status`→三态、`dueDate`、`description`（若有）。
- 其余字段丢弃或写入不展示的 `legacyPayload`。
- 默认可保留「经典任务流」入口；默认导航走新工作台；**不双写**。

### 明确不做（v1）

个人任务上云/跨设备、E2E 加密、细粒度字段同步、日历/四象限/番茄钟进新壳、主机离线时的多人编辑、CRDT。

### 验收标准

1. 未连网：个人 + 主线两块；能建、能完成、能拖入本机主线。
2. 连网：出现「所有人」；提交带作者名；仅负责人能推进团队主线。
3. 换项目 = 换内容；无旧任务流工具栏那堆默认入口。
4. 主机下线后个人仍可用；共享面正确降级。

## 建议模块划分（实现时）

| 模块 | 职责 |
|------|------|
| `electron/workbenchHost.ts` | 开房 HTTP/WS（或等价）服务、成员注册、权限校验、广播 |
| `electron/workbenchClient.ts` | 加入、心跳、事件发送、断线检测 |
| `src/modules/workbench/` | 项目列表、工作台 UI、三栏、拖拽、导入 |
| 本地持久化 | 个人任务 + 离线主线 + 项目元数据（userData JSON 或现有存储风格） |
| 主机持久化 | 房间内项目的 pool + mainline + 成员/负责人 |

具体协议与文件路径在实现计划中细化；本规格只锁定产品与权威边界。

## 与旧「简化任务流」的关系

本设计满足原简化目标（少入口、少字段、可维护），并通过**项目 + 三层空间 + 局域网主机权威**给出新的主工作流，而不是在现有 16k 行 taskflow 上继续堆功能。
